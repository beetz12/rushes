# Rushes commercial browser service

This is the separate account service for `browser/`. It does not alter the personal `worker/`, its URLs, the Mac recorder or its credentials. Local capture and static assets work before cloud providers are configured; hosting, Google sign-in and billing fail closed when their required settings are missing. There is no production fixture login or provider bypass.

The API follows `browser/src/contracts.ts` and the reviewed run contract. Google authorization uses a dedicated NexAI Rushes web OAuth application, a ten-minute one-use state/nonce, PKCE and server-verified Google RSA keys/issuer/audience/expiry/email. Opaque session and CSRF cookies are Secure, HttpOnly and SameSite=Lax. Sessions last up to 24 hours, rotate after six hours and have a fourteen-day absolute lifetime. Each Google login creates an independent session family. Rotation atomically replaces its current token; CSRF-valid logout from a current or rotated ancestor token revokes the whole family, including concurrent or late rotations. A fresh Google login creates a fresh family. Migration `0003` revokes pre-upgrade sessions once because their lineage cannot be established, so existing browser users must sign in again. Account creation requires a verified invited email and remains capped at 25 accounts; turning signup off still permits existing invited accounts to sign in.

`DB` binds the new private D1 account database, `RAW` the new private R2 raw bucket, and `ASSETS` the built browser assets. Apply the numbered forward migrations in order (`0001_browser_service.sql`, then `0002_provider_budget_safety.sql`, then `0003_session_families.sql`) to the separate database, never the existing personal database. The standalone `schema.sql` is the cumulative current schema for fixture/bootstrap tools. An existing database initialized from the old schema must explicitly apply `0002`; running current CREATE IF NOT EXISTS statements does not replace its old reserve trigger. Take an export first. The upgrade rebuilds modeled delivery counters from durable reservation rows and adds nonnegative guards; it does not claim a provider invoice reconciliation. The rollback file lives under `migrations/rollback/` to prevent automatic forward application; take a database export before a rollback and restore that export to recover data. Deployment, account verification and provider activation belong to the root runbook.

Required origin/settings and secrets:

| Setting | Purpose |
|---|---|
| `PUBLIC_BASE_URL` | Exact HTTPS origin, with no path/query/credentials; Google redirect URI is this origin plus `/auth/google/callback`. |
| `REVISION` | Tested deployed source revision shown by `/api/config`. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Dedicated Rushes NexAI Google web OAuth client. |
| `SESSION_SECRET` | Random secret of at least 32 characters for upload/share capabilities. |
| `INVITE_EMAILS`, `ACCOUNT_CAP` | Comma-separated verified pilot emails, and cap from 1 to 25. |
| `SIGNUP_ENABLED` | Explicit `true` to permit invited new accounts; default `false`. |
| `HOSTING_ENABLED`, `DELIVERY_ENABLED` | Explicit `true` after provider checks; default `false`. They stop new upload and media grants. |
| `STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID`, `STRIPE_WEBHOOK_SECRET` | NexAI test-mode key, server-selected active USD 1500-cent/month licensed price, and endpoint signing secret. |
| `STRIPE_LIVE_ENABLED` | Default `false`; live keys are rejected unless explicitly enabled after launch approval. |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | Verified account and server-only Stream API access. No vendor token reaches assets or browser storage. |
| `STREAM_CUSTOMER_CODE` | Stream customer subdomain code for signed iframe/MP4 URLs. Signing keys are not required: the service calls the authenticated `/token` API with its explicit expiry and policy. |
| `PILOT_BUDGET_USD`, `PILOT_WARNING_USD` | Modeled monthly application budget target, default $100 and $75 warning. Budget target cannot exceed $100 in this pilot implementation. |

Blank optional values are treated as unconfigured. Store real secrets using provider secret bindings or a private ignored local file, never this template. Configure a Stripe test webhook at `/api/billing/webhook` for subscription, invoice, refund and dispute changes. Hosted Checkout and portal use the trusted tenant/customer mapping. Neither success URLs nor submitted prices grant entitlement. The pinned Stripe REST version is `2024-06-20`; the service validates the allowed price and reconciles current subscriptions, paid invoices and charge refund/dispute state. Events are raw-body HMAC-verified, durably claimed and retryable after failures. Scheduled maintenance also reconciles current billing state when configured. Seven-day failed-renewal access grace does not delete videos prematurely: final cancellation begins the thirty-day composed export grace. Operator suspension is separate from billing state (`suspended_by_operator=1`) and survives later payment events.

Raw grants bind the authenticated tenant, recording, track, sequence, method, exact MIME, bytes, SHA-256 and fifteen-minute expiry. SQLite triggers reserve accepted plus pending bytes below 2 GiB; duplicate content acknowledges safely and changed content conflicts. Each body is bounded to 16 MiB with a 45-second read deadline, the first chunk has a WebM header, and acknowledgement follows private R2 metadata/size read-back. One raw body is admitted per Worker isolate to bound simultaneous buffers, with at most three durable write leases per tenant; contention returns retryable `RAW_CONCURRENCY`. Uploads use the server-built `t/<tenant>/r/<recording>/` prefix. Private original chunk GET supports one bounded range and verifies retained bytes against their digest. Raw expiry is seven days; local originals remain until the owner deletes them.

Finalization verifies ordered, complete raw descriptors and reserves a full 600 seconds against both 100 monthly upload minutes and 300 retained minutes before requesting Stream. Browser-reported duration never settles those quotas. Stream tus creation includes `requiresignedurls` immediately, a 600-second maximum, a one-day expiry and a server-derived64-character creator identity. New finalization markers are versioned so legacy recorded creator associations are verified with their original tag rather than silently reassigned. The service saves the returned UID/URL association before exposing it. Processing checks trusted UID/creator, privacy, readiness and actual provider duration before marking a video ready and settling the reservation. Retrying identical finalization returns the same still-valid resource. An expired resource is replaced only after its provider state and deletion read-back are confirmed. A failed/missing mapping, process termination, network loss, malformed response or HTTP5xx retains the durable creation marker and its reservation. Cleanup reloads the current row and reconciles that marker even if an error write never succeeded. It requires a complete exact-creator count and UID/creator read-back before deletion; failed or incomplete read-back leaves the recording quarantined. Only an explicit structured API validation/authentication rejection can be treated as a definite non-creation. It never blindly creates another asset.

Library videos remain private. The account list uses bounded fifty-record pages, an opaque validated createdAt/id cursor and stable descending ordering, with a tenant predicate on every page. Aggregate summaries avoid per-record database calls. Explicit unlisted links can have a password and expiry; passwords use salted PBKDF2 and rate-limited unlock, whose cookie is bound to share/tenant/recording/policy version. Changing policy or deleting a recording immediately prevents new grants. Each explicit playback token request reserves the full clip duration, with a three-session tenant concurrency limit and 1000-minute monthly delivery allowance. Playback tokens cover the provider clip duration plus 120 seconds, capped at twelve minutes; they do not permit downloads. Owner export separately enables/checks provider MP4 generation, then reserves delivery and issues an individual downloadable token capped at five minutes. There is no public share export or bulk download endpoint. Exact Cloudflare connection IP restrictions are included when available.

Already-issued signed tokens can remain usable for up to twelve minutes after revocation, and can be replayed while valid. Provider buffering, downloads and analytics lag can add billable delivery. The application quota and modeled budget are not a hard provider invoice ceiling. The public config reports validated billingMode as test, live or unconfigured; live keys still require the explicit live flag. Live launch must test practical token replay exposure and reconcile provider metrics/invoices. A new explicit token spends another full-clip reservation; there is no hidden free renewal path.

The calendar-month application estimate atomically gates new storage slots, raw reservations, delivery grants and selected media-operation attempts. In USD cents it is:

`500 + 500*ceil(global retained-and-reserved seconds/60000) + ceil(month delivery seconds/600) + ceil(month peak raw bytes*15/10000000000) + ceil(media operation units/100)`.

The first term reserves Workers base cost; Stream capacity counts retained plus outstanding duration reservations in 1000-minute blocks. The raw term conservatively models a full month of peak accepted/pending raw bytes at $0.015/GB without a free allowance. The last term reserves one cent per 100 selected media operations, deliberately conservative compared with the ordinary plan's operation assumptions. A single reservation timestamp binds delivery charge, cap check and release to the same immutable calendar month, including concurrent UTC rollover. Failed unissued playback grants release their tenant/global delivery reservation; failed provisioning remains held safely until verified retry/deletion or abandonment. Storage reservations release after verified cleanup; monthly raw peaks and attempted operations remain charged in the model. `applicationBudget` in the library response reports this estimate and warning, not a vendor invoice. Conservative operation reserves can stop grants before a tenant uses its advertised minute allowance. Measure and reconcile actual provider operation/CPU/index costs before selling the proposed allowance. Shared-account services, provider latency/replay, tax, support, AI, domains and billing losses are not guaranteed bounded by this model.

Maintenance should run at least hourly. It revokes access before cleanup, removes abandoned drafts/uploads after 24 hours and raw objects after seven days, and removes canceled-account hosted videos after export grace. It narrows every bucket operation to a trusted exact tenant/recording prefix, checks absence of Stream/R2 data before `deleted`, and retains errors for retry. In-flight write leases prevent a concurrent late write being declared deleted. Aggregate maintenance logs contain counts, not footage, passwords or signed URLs. Deploy alerts should watch `pending`/`billingPending`, `cleanup_error`, modeled warning and provider budget/delivery metrics. Operator provider failures never report cleanup complete.

Use Node 22.22.0: `npm ci`, then `npm run check` in this package. Tests use real SQLite foreign keys/triggers and real RSA/HMAC cryptography; fetch/R2/clock fixtures are confined to `test/`. They establish local behavior, not a configured Google login, real Stream ingestion/playback, billing identity or a live payment. Those remain deployment gates, together with private provider-origin anonymity, browser support/capture tests and independent review.
