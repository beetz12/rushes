# Input frame lifetime across composition

A borrowed camera or screen VideoFrame must be closed after its pixels and timestamp have been consumed synchronously. An asynchronous write of a separately constructed output frame must not prolong that application-owned input lease. Closing the input object does not prove immediate capture-pool or GPU resource reclamation.

For mixed screen and camera composition, copy each arriving screen into an owned output-sized raster while it is live. Clear every raster update to the same #101820 letterbox and preserve the current fit and alpha behavior. Copy the raster1:1 into the output; draw the current camera/bubble while its frame remains live, then create the output VideoFrame using the unchanged driver timestamp. Screen-only and camera-only modes keep their direct fit path. Close every input in finally before invoking the asynchronous output writer. Close the owned output only after write settles. Cache updates must survive cadence rejection; early camera frames and late input after Stop must close without output.

Retain the current frame-admission buckets, limit/pause controls, pixel layout, first-screen gating, and ready/progress only after successful writes. No heartbeat, fabricated source timestamp, new input reader, source-profile change, native acknowledgement substitution, or timing/recovery waiver is introduced. Canvas bitmap semantics and real decoded pixel controls supplement controlled backpressure/exception tests. Source-only calibration failures are separate and cannot be claimed repaired from these ownership tests.
