# Mac releases and explicit update restarts

A Mac release needs both a disk image for first installation and a ZIP for the maintained updater. Both come from the same packaged application, with the existing native automation helper prepared before outer signing. Development packaging requires an explicit development choice and signing identity. It never enables application updates. Distribution additionally requires the existing Developer ID/notarization policy and an explicit public HTTPS release directory. Building does not publish.

After a successful build, require the exact ARM64 DMG and ZIP pair for the package version. Hash actual artifact bytes and emit small JSON metadata containing their names, lengths and SHA512 digests. This manifest reports bytes, not an invented signature or notarization verdict. Actual signing, accepted notarization/stapling and installer/update execution remain separate release gates. Use a newer stable package version than the installed0.1.0 baseline.

Store only update policy and the public feed URL inside the app before signing. No provider credentials, GitHub token, owner sharing token or runtime environment override belongs in the client. Disabled development policy must remain disabled when copied into another environment.

Use pinned electron-updater6.8.11 and its exported custom-provider interface. Read the public JSON manifest once with an absolute request deadline, no redirects or credentials, and a64KiB body limit. Validate fixed schema, application/platform/architecture identity, stable version, two bounded artifact sizes, canonical SHA512 values and exact versioned basenames. Resolve assets only under the signed configuration's HTTPS directory. Upstream code retains download checksum verification and native Mac signature/install handling; no platform updater is reimplemented.

The coordinator is the sole capture-activity authority. Automatic checks/downloads begin only while idle. A capture-activity notification cancels pending downloading and invalidates late callbacks. Missing or unknown activity refuses a restart. Automatic installation on quit stays disabled; only an explicit user restart request can invoke the native installation path, after another idle check. The module exposes a restart latch for the coordinator to reject new takes. Once native quit/install is committed the latch cannot be cleared by a late error or timer, since that native action has no safe public cancellation API. No automatic restart occurs during a take.

Keep download cancellation and check failures visible without claiming installed success. Bound metadata requests and whole download time; validate actual downloaded length before presenting readiness. Keep periodic scheduling finite and dispose owned timers/listeners when the coordinator shuts down. Pure controls must exercise real policy/provider/controller code, including malformed/oversized feeds, redirects, wrong asset identities, capture races, late callbacks, cancellation, explicit restart, and errors after native restart commitment. Mock ports are not signed-app or installed-update evidence.

Primary contracts inspected: official electron-builder v26 update/API documentation; pinned electron-updater6.8.11 registry tarball and its MacUpdater/AppUpdater/provider-factory sources; pinned builder26.15.3 packaging/signing interface. No reference-recorder code or assets were used.
