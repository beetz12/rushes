# Durable post-Stop jobs

The plan requires speech recognition to start after Stop in the background, keeping review and sharing available. Words remain on the source recording timeline; metadata comes from the real transcript. Sharing enrichment projects words through the frozen published edit and keeps the same video and URL. This implementation is original; no reference source is opened or copied.

Each recording package holds one versioned jobs.json ledger. Every queued job is persisted before work starts; each attempt is persisted as running before its executor runs. Native work is serial and runs at utility priority. Dependencies order transcription, metadata, then enrichment. Completion is recorded only after the expected artifact validates or the real desktop bridge returns a successful enrichment response. Empty recognition output is a valid completed transcript; missing audio, models, permissions and invalid output are errors.

Full package verification is an independent, lowest priority job. Stop returns after writer finalization and queue persistence, without waiting for full decode. Only PackageVerifier's real full decode result writes verification.json and the compact manifest stamp. A failed track produces verification-failed with the report artifact, preserving the original package status and masters. Cancellation prevents a stamp write. Root's verifier must check cancellation between tracks and decoded samples; Trash waits for the executor to actually stop before moving files.

Transcription never downloads assets by default. Only an explicit allowAssetDownload request grants that action. Metadata uses the on-device model by default and exposes errors; an explicitly requested extractive mode is labelled as such. A generated result cannot overwrite metadata or a title changed while generation was running.

Interrupted running attempts become queued on restart, retaining their history. Failed enrichment caused by the desktop being unavailable uses bounded persisted retry delays and can retry when the app returns or the engine restarts. User cancellation stays cancelled. Capture activity pauses new native work so recording remains the foreground task. Corrupt or escaping ledgers are reported and preserved, never silently replaced.

The native enrichment executor forwards share.enrich through the existing private user-owned ShellServiceBridge socket. It checks response.ok and the returned updated flag. A recording which is not shared is recorded as an explicit cancelled/not-applicable enrichment, not successful delivery. Provider/app errors remain failed with retry history. The broker never reads credentials or publishes through another channel.

Root integration owns prepare/resume, post-finalize enqueue, capture activity hooks, command routing and job event broadcasting. It must replace the previous try?-and-ignore enrichment call with queueEnrichment. The desktop must stop duplicating enrichment on manual transcript/metadata completion once this queue owns that work. No additional remote implementation is introduced here.

An example user workflow is jobs.list with a recording id, followed by jobs.retry with that jobId and allowAssetDownload=true only when the user requests a speech asset download. For unavailable Apple Intelligence, retry the failed metadata job with metadataMode=extractive; the artifact labels its actual extractive engine. jobs.cancel persists cancellation. A desktop-required error prompts opening Rushes; processing remains retryable while the reserved share finishes. Unknown desktop responses cannot become successful jobs.
