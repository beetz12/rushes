# Loom recording parity scorecard — 2026-11-06

Branch `claude/loom-parity-20261106` (from `codex/rushes-production-20261022` 2e01c94).
Clean-room: this list names Loom's public, user-visible recording features only.
No Loom code, assets or UI were copied or inspected.

## Method

Each capability is scored for a desktop-app user, not for the CLI:

- **FULL = 1.0**: engine support and a reachable shell control.
- **PARTIAL = 0.5**: engine/CLI only, a stub, or a missing piece named below.
- **NONE = 0**.

Weights: **3** = core to every Loom-style take, **2** = expected by regular users,
**1** = nice to have. Score = earned weight / total weight.

Evidence is static: code paths and unit tests. Real capture (screen, camera, mic)
needs David's sensor approval, so no row here is proven by a live recording.

### What these numbers do not prove

- No row is proven by a live screen/camera/mic recording. Engine paths use the
  repo's generated capture rigs; shell UI was checked with unit tests and
  screenshots of the renderer against a stub bridge.
- #3 quality: the cap math is unit-tested; the controller test's fixture display
  is small, so it proves acceptance and "never enlarges", not a real 4K→1080p cap.
- #10 noise suppression is applied when exporting or sharing, not to the live
  mic master. That keeps Rushes' untouched-tracks promise; Loom cleans audio at
  capture. Its test uses a voice generated by `say` plus synthetic noise.
- #20 (do-not-disturb / hide desktop clutter) is not built. macOS offers no
  public API to switch Focus on; hiding desktop icons would rewrite Finder settings.
