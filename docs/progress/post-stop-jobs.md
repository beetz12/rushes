# Durable post-Stop integration

New module contract: PostStopJobService owns versioned per-package jobs.json. Root creates one service for the recordings root, injects NativePostStopJobExecutor with a real ShellServiceBridge.forward share.enrich closure and currentEdit closure from the same PostproductionService. Call setArtifactDidWrite after router initialization to refresh canonical index state; setEventSink forwards PostStopJobEvent as JSON via postStopJobJSON. Static commands are jobs.list, jobs.retry and jobs.cancel; handle takes ControlRequest.

Root prepare calls resume. Root finish persists enqueueAfterStop before broadcasting recording-stopped, without awaiting recognition. Capture begin calls setCaptureActive(true); failed begin and finalized stop call setCaptureActive(false). Shutdown persists interruption then cancels background tasks. Before Trash, await cancelRecording(id), which persists cancellation, blocks new scheduling, and waits for executor plus artifact callback; restore calls allowRecording(id). Ordinary restart never retries cancelled jobs.

enqueueAfterStop now also persists an independent verify job. Across eligible work, verify runs after transcription, metadata and enrichment. Native verification fully decodes package media and writes verification.json plus the manifest verified stamp using that real result. Failed decode persists verification-failed and report artifact; recovered package status remains recovered. Root removes full decode from Stop and adds cooperative reader cancellation checks in its owned PackageVerification implementation. Existing synchronous verify remains full.

Manual transcript/metadata mutations call queueEnrichment instead of the previous try?-and-ignore forwarding. Native executor checks response.ok AND updated=true. Processing is a retryable share-processing error. Explicit no-state/unshared is not-applicable cancelled, never successful delivery. Failed app/network operations keep retry timestamps/history. Desktop must not duplicate that queue-owned operation.

Model assets never download by default; jobs.retry requires explicit allowAssetDownload=true. Apple metadata failures are surfaced. Extractive mode is an explicit retry option. Metadata rereads transcript, metadata, title, on-disk edits and optional live edit state before writes; existing user metadata and supplied fields are preserved. Canonical generated title is updated only for an untitled take without user title.

These are synthetic/local tests, not live speech recognition or external delivery.
