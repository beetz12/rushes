# Native Rushes Shortcuts

The original Swift actions send record.start/record.stop over the existing current-user private control socket. They open no capture devices and never launch a real engine. Camera/microphone default Off. Open Rushes and finish its permission setup before invoking production actions. Stop returns the finalized package folder path; invalid or failed engine results throw an actionable error.

Build/gates from repo root:

- `swift test --filter IntentTests`: five actual AppIntent/pure argument/private socket tests with a stub ControlHandling implementation.
- `python3 scripts/app-intents/metadata.py --configuration debug --bundle-id <owner-bundle-id> --output <stage>`: actual compiler constants plus appintentsmetadataprocessor extraction; validates both native action types in output.
- `LOOM_LIVE_TESTS=0 /bin/bash scripts/check.sh`: full repository gate with the repository's existing opt-in live hardware suites disabled. No new test skips are added.

Root-approved Package.swift targets are RushIntents (depends RushCore), RushIntentsExtension executable (depends RushIntents), and RushIntentsTests (depends both). The executable has two supported compilation modes. The main-process automation helper mode uses `RUSHES_INTENTS_MAIN_HOST`; QA additionally uses `RUSHES_INTENT_QA` and a QA-only bundle identifier. QA defaults fail closed to an unavailable socket if the signed stub override does not match, so a test can never select the real engine.

Preferred local packaging candidate after the observed ExtensionKit constraint: `python3 scripts/app-intents/host-package.py --output <fresh-path>/RushesAutomation.app --sign-identity <existing-stable-local-certificate>`. It builds the main-process host, extracts actual metadata into its Resources, and signs/verifies the helper without app groups, provisioning profiles, sandbox exceptions or extra entitlements. Embed it under Rushes.app/Contents/Helpers/RushesAutomation.app and sign the containing Electron app after embedding. Register only that final helper using the standard LaunchServices installation/registration path. Root owns final install/signing and testing against the running app. Main-host execution on macOS27 is explicitly selected in metadata; macOS26.4 fallback still needs actual device/OS verification.

The ExtensionKit `.appex` candidate is also provided by package.py. The SDK requires Contents/Extensions (not legacy PlugIns). Its actual metadata extraction and signature passed, and its action catalog appeared, but its ExtensionFoundation registration stayed at0 and the scoped shortcut failed action lookup. See the recorded CONSTRAINT in docs/design/app-intents.md. Do not claim that variant works or add security grants/profiles to bypass the requirement. Public `DiscoveryProbe.swift` distinguishes real ExtensionFoundation registration from merely visible action metadata.

Scoped QA steps (do not touch other shortcuts): start `stub.py --socket /tmp/rushes-iqa/control.sock --log <owned-log>`, build a fresh helper with `host-package.py --configuration debug --bundle-id com.nexai.rushes.intentqa --qa-socket /tmp/rushes-iqa/control.sock --output <fresh-qa-path>/RushesAutomation.app --sign-identity <certificate>`, register it, and launch only that helper. Create uniquely named Rushes QA Start/Stop shortcuts using those native actions. Confirm the descriptors refer to the QA bundle and camera/mic Off before running them. Run via `shortcuts run 'Rushes QA Start'` and Stop, then verify the dedicated stub log shows one start/stop and the output id/path. QA apps are separately identified, compile-time stub-only and contain no engine/capture startup. Do not run QA shortcuts against production.

Unsigned scoped production assets are under assets/. They are prepared templates and have not been imported or executed against the final application. Generate fresh exact-bundle assets with shortcut-assets.py after the final helper's identifier/signing team is selected. Signing/import must use Apple's normal trusted Shortcuts flow; do not enable an insecure-import setting or change security/privacy settings. Exact import: after trusted signing, open the corresponding Rushes Start/Stop Recording shortcut file in Shortcuts, inspect its action's app identifier and Off defaults, then choose Add Shortcut. Alternatively create a new shortcut, search Rushes Automation, add Start Recording or Stop Recording, name it explicitly, and save. `shortcuts list` lists saved workflows; action catalog discovery does not itself create a named workflow for `shortcuts run`.

Current evidence: native methods + protected stub round trips pass, metadata and local signatures pass, Shortcuts catalog contains both actions. Actual saved-workflow execution is not yet verified: the extension candidate failed action lookup; the main-process candidate is signed and metadata-complete, but its first launch/UI proof was blocked by the Mac locking. No real camera, microphone, screen/audio capture, cloud writes or remote profile changes occurred. Unlock is a user-owned prerequisite; do not bypass it through another input mechanism.
