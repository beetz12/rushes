# Rushes share viewer

Framework-free, original TypeScript player. Build with Node 22.22.0: `npm ci --prefix viewer && npm run build --prefix viewer`. Assets: `viewer/dist/viewer.js`, `viewer/dist/viewer.css`. `cloud.viewerPage` generates the HTML from escaped metadata, including same-origin CSP and crawler-visible Open Graph. The page-template file documents its inputs; no unescaped string substitution is used.

The viewer polls processing status every 3 seconds for up to 10 minutes, then displays the MP4 with native controls/captions, speed, timed-link copying, download, transcript seek and chapters. Worker mode adds passwords, timestamped comments/reaction controls and playback-session counting. DOM inserts use textContent. No external requests or tracking. Bucket mode uses no cookies; password Worker mode uses the secure unlock cookie.

`npm test --prefix viewer` runs actual Chrome and Playwright WebKit locally on an original generated 8-second H.264 fixture. Install test browsers with `npm exec --prefix viewer playwright install chromium webkit`; Chrome must be installed for the branded Chrome run. Tests exercise processing-to-playable transition, actual frame playback, captions off/on, transcript seeking, chapters, speed, escaping and a 390-pixel viewport. This is browser-engine QA on generated media, not Safari/iOS-device QA or a cloud network test. The fixture was generated by local ffmpeg for testing; no ffmpeg is shipped or used by the application.

Cue state refreshes when a transcript arrives, after seeks and media changes, and on visibility/ending events. A hovered inactive row has a neutral background; the active cue keeps its blue fill and left accent, with a separate keyboard focus outline. Tests at 375 CSS pixels cover paused late transcripts, natural endings, media replacement and these visual states. Both engines measure the unchanged footer foreground/background contrast at 5.5749:1. The native ending already cleared active cues in the prior implementation; the reproducible fixes concern late row creation and ambiguous hover styling. macOS WebKit keyboard checks use Option-Tab, verified in a controlled browser probe and documented in [Apple’s keyboard guidance](https://support.apple.com/guide/safari/keyboard-shortcuts-and-gestures-cpsh003/mac).
