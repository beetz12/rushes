# Rushes share Worker

Original Cloudflare Worker, R2 and D1 service. No copied reference source or runtime dependencies. Build viewer first, then `npm ci --prefix worker && npm run check --prefix worker` with Node 22.22.0. `worker/dist/worker.js` is a self-contained ES module including viewer assets; `worker/schema.sql` is idempotent D1 setup.

Bindings: R2 `MEDIA`, D1 `DB`, secrets `OWNER_TOKEN` and `SESSION_SECRET` (random strings of at least 32 characters), plain `PUBLIC_BASE_URL` (HTTPS Worker/custom-domain origin). Optional comma-separated `ALLOWED_ORIGINS`, `MAX_UPLOAD_BYTES` (default 50 GiB). Owners use bearer auth on `/api/shares`, upload orchestration, publishing, metadata, unshare and setup. Upload PUTs require expiring HMAC grants tied to one share, session, part, MIME type and byte count. JSON responses and errors have CORS headers for explicitly allowed origins; unknown origins are rejected.

Passwords require 8+ characters, PBKDF2-SHA256 with 100,000 iterations and random salt. Unlock responses issue a one-hour HttpOnly Secure SameSite=Strict cookie. Protected data/media use private no-store. Password attempts and feedback use atomic D1 rate counters and fail closed on database failure. Views count on explicit playback session events, never page or data fetches. Comments carry exact timestamps. Expiry denies reads immediately, and the daily cron removes R2 objects, incomplete uploads and database records.

Owner `GET /api/shares/:id/policy` returns only `{protected:boolean,expiresAt:string|null}`. Owner `PATCH` accepts `{password?:string|null,expiresAt?:string|null}`: omission preserves, null removes, a password has 8–1024 characters, and expiry must be a future ISO date/time with timezone. The whole patch validates before one atomic database update; policy never changes the ready manifest or stable URL. Salt and password hash remain database-only. Cookies carry an opaque keyed revision instead of password credentials; rotating the password creates a new salt and revokes earlier unlock cookies. Removing protection makes the share public, and adding it again never reactivates earlier grants.

Owner policy access remains available on expired rows until cron deletion, allowing the owner to remove or extend expiry. Public expiry checks still return 404. Owner unshare authenticates before cleanup and removes the exact validated share prefix even when expired or already deleted; it aborts outstanding uploads and confirms no objects remain. Repeating deletion returns 204, so a local upload job can be cleared after scheduled removal.

Deployment implementation: `cloud.deployWorker({accountId,apiToken,workerName,bucketName,databaseName,workersSubdomain,script,schemaSQL,ownerToken?,sessionSecret?})`. It checks R2 activation before writes, reuses matching resource names, creates missing storage/database, uploads bindings, enables workers.dev, sets `0 3 * * *`, then confirms HTTP health and owner-authorized storage/database read-back. The account ID is caller-selected; no environment scanning or guessed identities. R2 API code 10042 produces `R2_NOT_ENABLED` with the selected account and a Dashboard activation instruction. Do not automatically retry that state. Partial deployment never reports success; retain supplied secrets and resource names before retrying. Deploy only after the user authorizes the selected account/destination.

All tests run the actual Worker HTTP handler with controlled in-memory R2 and actual SQLite-backed D1 fixtures. The integration test also routes the SDK over real localhost HTTP. These tests prove local protocol behavior; they do not prove an actual Cloudflare deployment, paid-account activation, public connectivity or cron execution on the service.
